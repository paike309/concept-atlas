## 一句话定义

**中文**：并发读写同一内存位置且缺少同步时发生的、结果依赖于执行时序的缺陷，其根源是语言与硬件的内存模型允许重排与延迟可见。

**English**: A defect from concurrent unsynchronized access to the same memory, whose root cause is a memory model that permits reordering and delayed visibility.

## 我的理解

**竞态的本质是"代码假设了一个并不成立的执行顺序"。**

最容易低估的是它的**不可复现性**：竞态依赖线程调度与硬件行为，在开发机上可能一万次都不触发，在生产的高并发或不同 CPU 架构上立刻出现。这带来一个残酷的推论：**"测试通过"对竞态几乎没有证明力**——它只能证明这次没触发。

由此推出三条实践结论：

1. **不要用"看起来对"推理并发正确性，要用 happens-before 关系推理。** 问的不是"这两行代码的执行顺序"，而是"**有没有一条同步关系保证 A 的写在 B 的读之前可见**"。没有这条关系，任何顺序都可能发生——包括编译器把两句调换、CPU 把写缓冲住。
2. **语言的内存模型是唯一有效的规格。** "在我这台机器上没问题"不是论据：不同架构的内存序强弱不同，同一份代码在弱内存序平台上暴露，在强内存序平台上可能多年不暴露。
3. **能不用共享内存就不用。** 消息传递、不可变数据、单写者模型，都比"正确使用原子操作"更容易做对。**无锁编程的门槛不是知识，是验证成本。**

## 核心机制

**三个独立的问题常被混为一谈**：

| 问题 | 含义 |
|---|---|
| 原子性 | 一个操作是否可被观察到"执行了一半" |
| 可见性 | 一个线程的写，何时对另一个线程可见 |
| 有序性 | 编译器与 CPU 是否可能调整语句的执行顺序 |

**happens-before**：语言规范定义的偏序关系。**在两个操作之间没有 happens-before 关系时，读写可以以任意顺序被观察到**——这是推理并发正确性的唯一严肃工具。常见建立方式：锁的获取与释放、通道/消息的发送与接收、原子操作的特定顺序语义。

**典型误判**：

```
// 反例：flag 无同步
ready = true          // 线程 A
while (!ready) {}     // 线程 B —— 可能永远看不到
```

看起来"写在前、读在后"，但由于缺少同步，**可见性与顺序都没有保证**。修法不是"加个短暂休眠"，而是建立真正的同步关系（原子操作带合适的内存序，或互斥量）。

**无锁编程的真实成本**：CAS 循环需要处理 ABA 问题、内存回收（何时安全释放节点）、以及正确选择内存序。**用错的原子操作比加锁更危险**——它给出"我处理了并发"的错觉，却可能只是把竞态换成了更罕见的形式。

**检测手段**：

| 手段 | 能发现 | 局限 |
|---|---|---|
| 竞态检测器（如各类 race detector / TSan） | 运行期实际发生过的竞争 | **只能发现执行到的路径**，未覆盖的路径仍是盲区 |
| 静态分析 | 部分模式 | 误报多，难覆盖语义 |
| 压力测试 | 概率性触发 | 通过不代表正确 |

**竞态检测器应当进 CI**：它的价值不是"证明没有竞态"，而是**把"偶发"变成"必现"**——同样的路径在检测器下会稳定报出来。

## 边界：它不是什么

- **与[并发与锁](concurrency-and-locking.md)的区别**：那张卡讲"如何用锁建立互斥"，这张讲"**没有同步时会发生什么**"。锁是手段之一；这张卡关心的是**缺少同步关系**本身。
- **与[隔离级别](transaction-isolation.md)的区别**：隔离级别约束的是**数据库事务之间**的可见性；内存模型约束的是**进程内线程之间**的可见性。两者的推理工具相似（都需要一个"顺序保证"），但作用域完全不同。
- **与"死锁"的区别**：死锁是**进展性**问题（大家都不动），竞态是**正确性**问题（动了但结果错）。两者的症状与排查方式都不一样。
- **与"性能问题"的区别**：竞态表现为**随机的错误结果**，不是慢。**把它当性能问题排查会浪费大量时间。**

## 常见误解

1. **单核机器没有这个问题** → 编译器重排与线程切换同样能产生可见性问题；且迁移到多核就会暴露。
2. **加了 `volatile` 就解决了** → 它通常只处理可见性/有序性，不提供原子性（复合操作仍不安全）。
3. **测试通过 = 没有竞态** → 通过只说明这次没触发。
4. **用原子类型就安全** → 单个原子操作安全，多个原子操作组合起来仍不构成原子事务。
5. **竞态检测器没报警就没有问题** → 它只覆盖运行到的路径。
6. **无锁比加锁快所以更好** → 在验证成本与出错概率上，多数场景加锁更划算。

## 应用场景

- **该用消息传递/不可变数据**：能改设计就改设计，这是成本最低的路径
- **该用锁**：临界区清晰、冲突不极端时的默认选择
- **才考虑无锁**：确有性能证明（剖析显示锁竞争是瓶颈），且有相应的验证手段与人力
- **判断依据**：问一句——**"这两次访问之间有 happens-before 关系吗？"** 答不上来就当作不存在
- **配套**：把竞态检测器加进 CI 与压测；并发相关的线上故障要在[可观测性](observability.md)里能关联到线程/协程上下文
