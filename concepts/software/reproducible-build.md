## 一句话定义

**中文**：相同源码与相同构建配置，在任意时间、任意机器上产出完全相同的构建产物。

**English**: Building the same source with the same configuration produces bit-for-bit identical artifacts anytime, on any machine.

## 我的理解

它解决的是"**这个二进制到底是不是这份源码编译出来的**"这个可验证性问题。

没有可复现构建时，你只能靠**信任流程**（CI 可信、构建机干净）。有了它，任何人都能重新构建并比对哈希——**信任从"流程"变成"可验证的事实"**。

对供应链安全尤其关键：**构建不可复现，就无法排除构建环节被注入的可能。**

常见的不可复现来源（都需要主动消除）：

| 来源 | 说明 |
|---|---|
| 时间戳被写进产物 | 最常见的来源 |
| 文件系统遍历顺序 | 依赖底层实现 |
| 构建路径编进二进制 | 绝对路径泄漏 |
| 依赖版本未锁定 | 解析到不同版本 |
| 并行执行导致顺序变化 | 非确定性汇编顺序 |
| 随机数、UUID、环境变量 | 直接引入不确定性 |

一个必须分清的概念对：

- **可重现**：我能重建出来（通常就够了）
- **可复现**：**逐字节相同**（成本高得多）

**要区分你实际需要哪一个**，不要默认追求字节级。

## 核心机制

- **依赖锁定**：锁文件 + 校验和，避免"同一份代码解析出不同依赖"
- **环境固定**：编译器版本、基础镜像、环境变量都固定下来（容器镜像是常见手段）
- **消除非确定性**：normalize 时间戳、固定遍历顺序、去掉绝对路径
- **验证方式**：两次构建比对哈希；或在**不同的机器与路径**下构建比对
- **传递信任**：签名 + 构建证明（attestation），让使用者能验证产物确实来源于指定源码
- **在审计链中的位置**：可复现构建与[版本号](semantic-versioning.md)、[变更日志](changelog.md)共同回答"这个版本从哪来"

## 边界：它不是什么

- **与"可重现"的区别**：见上。这是最需要先分清的一对。
- **与容器化的区别**：容器固定**环境**，但不自动保证产物一致（容器内仍可能有时间戳与路径差异）。
- **与锁文件的区别**：锁文件是**必要条件，不是充分条件**——还有环境与流程。

## 常见误解

1. **用了容器就可复现** → 容器内仍可能存在时间戳、路径、遍历顺序的差异。
2. **锁文件就够了** → 只解决了依赖解析，环境与构建流程仍是变量。
3. **所有项目都需要字节级可复现** → 很多场景只需要"能重建"。
4. **可复现能防止构建被攻击** → 它让攻击**可被发现**；要形成防御还得配合签名与验证。

## 应用场景

- **该追求字节级**：对外分发二进制、受审系统、供应链安全要求高、需要长期归档重现
- **只需"能重建"**：内部服务、生命周期短的项目
- **判断依据**：问"**我需要的是能重建，还是需要能证明这个产物确实来自这份源码？**" 后者才需要字节级
