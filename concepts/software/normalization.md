## 一句话定义

**中文**：范式化按函数依赖拆分数据以消除冗余和更新异常；反范式化是有意引入冗余，换取读取效率。

**English**: Normalization splits data along functional dependencies to eliminate redundancy and update anomalies; denormalization deliberately reintroduces redundancy for read performance.

## 我的理解

**范式化解决的是写入正确性，不是"规范整洁"。**

它要对付的具体问题是：**同一个事实存了多份，改一份忘一份，数据库里就出现了互相矛盾的真相。** 这类矛盾比性能问题更难发现——查询能跑通，只是答案悄悄错了。

由此推出反范式化的真实前提：**它不是"随便冗余"，而是"接受一份冗余，并明确谁是权威、什么时候同步、不同步会怎样"。** 没有这三个答案的冗余，不是设计取舍，是缺陷。

判断依据可以压缩成一句话：**这份冗余如果不同步，业务能忍受多久？**

- 能忍几分钟到几小时（报表、搜索索引、推荐特征）→ 可以冗余
- 一秒都不能错（余额、库存、额度）→ 保持范式化

真实系统几乎都是混合的：核心交易表范式化，读取侧用物化视图、宽表或检索引擎冗余。**关键是每条冗余都能指出它的权威源。**

## 核心机制

**范式化针对的三类更新异常**：

| 异常 | 表现 |
|---|---|
| 插入异常 | 想记录一条事实，却因为缺少主键信息而记不进去 |
| 删除异常 | 删除一行，顺带丢掉了另一条本应保留的事实 |
| 更新异常 | 同一事实存在多处，只更新了其中一处 |

**主要范式（到 BCNF 为止，工程上通常够用）**：

| 范式 | 消除什么 |
|---|---|
| 1NF | 非原子字段（重复组、逗号分隔列表） |
| 2NF | 非键字段对**主键的一部分**的依赖 |
| 3NF | 非键字段之间的传递依赖 |
| BCNF | 所有决定因子不是候选键的情形 |

越往上拆，表越碎、JOIN 越多。**工程上的常见落点是 3NF 或 BCNF，不是"越规范越好"。**

**反范式化的常见形式与代价**：

| 形式 | 同步方式 | 代价 |
|---|---|---|
| 冗余列 | 同一事务内一起写 | 写入路径变复杂，容易漏改 |
| 汇总表 / 物化视图 | 定时或事件触发刷新 | 读到的是"上一版"，要定义刷新窗口 |
| 宽表 / 读模型 | 异步管道（CDC、消息） | 必须定义不一致窗口内读取方的行为 |
| 专用检索索引 | 异步同步 | 索引与主库可能短期不一致 |

**约束能兜住哪一部分**：唯一、外键、非空、检查约束能让数据库拦住**结构层**的矛盾（重复、悬空引用、越界值）。但"两边余额之和不变"这类**业务不变式**不属于约束的表达范围——那需要[事务](transactions-acid.md)加应用逻辑。

## 边界：它不是什么

- **与[领域模型](domain-model.md)的区别**：范式化约束的是**存储结构**（表怎么切、依赖怎么消除），领域模型约束的是**行为归属**（规则写在谁身上）。两者正交——可以同时满足，也可能冲突：聚合边界是按不变式划的，与 3NF 的表划分并不总是一致，这时需要一个映射层，而**这个映射层是有代价的，别假装它不存在**。
- **与[索引](index-and-query-plan.md)的区别**：索引解决"定位快不快"，范式化解决"数据会不会互相矛盾"。**加索引修不了更新异常**——那是两份数据的问题，不是查找速度的问题。
- **与"没设计好"的区别**：反范式化是**有意且可管理的**冗余（有权威源、有同步机制）；建模失败留下的冗余是**意外的**冗余。区别不在有没有冗余，在有没有人负责同步。

## 常见误解

1. **范式化已经过时** → 它解决的是写入正确性，只要系统还有写入，问题就还在。
2. **反范式化就是不加约束、随便冗余** → 没有权威源与同步机制的冗余是缺陷，不是取舍。
3. **必须严格 3NF，或者干脆全反范式** → 两种教条都错，依据是"这份不一致能忍多久"。
4. **用 JSON 列就不用建模了** → JSON 把建模问题**推到应用层**，没有消除它，只是让它不受约束检查。
5. **冗余列只是多占点空间** → 真正的代价是**写入路径变复杂**，以及未来某个改动忘同步导致的静默错误。

## 应用场景

- **该范式化**：核心交易数据、有复杂不变式的表、写入频繁且要求一致的场景
- **该反范式化**：读多写少、可容忍延迟一致、且读取侧瓶颈已被测量证实的场景
- **判断依据**：写下三条——**权威源是谁、多久同步一次、不同步会怎样**。写不出第三条，就不要冗余
- **落地顺序**：先范式化建模，等出现**可测量**的读瓶颈再反范式化。倒过来做很难回退——已经散落各处的冗余，事后无法判断哪份是权威
