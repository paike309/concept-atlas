## 一句话定义

**中文**：声明代码应满足的通用性质，由工具自动生成大量随机输入来寻找反例的测试方式。

**English**: Stating general properties the code must satisfy, then letting a tool generate many random inputs to find counterexamples.

## 我的理解

它与示例测试的差别是**量词不同**：

- 示例测试：**对于这组输入**，结果正确（存在量词）
- 属性测试：**对于所有**满足某条件的输入，某性质成立（全称量词）

这个转变带来两个好处：

**1. 覆盖人类想不到的输入。** 人写测试时会本能地回避自己没想清楚的地方；随机生成不会。**第一次跑属性测试，通常会发现几个自己从没考虑过的边界。**

**2. 失败时自动收缩（shrinking）。** 找到反例后，工具会把输入逐步简化到最小反例，让人不必面对一堆随机数据。这是它比裸随机测试好用的关键。

## 核心机制

**常见性质类型**：

| 类型 | 例子 |
|---|---|
| 不变量 | 排序后长度不变 |
| **往返一致性** | 编码再解码应得到原值 |
| **等价性** | 新实现与旧实现对同一输入结果一致 |
| 幂等性 | 重复执行结果不变 |

**为什么"等价性"很实用**：重构时，它与重构验证天然契合——旧实现就是参照物。

**为什么"不变量"比"具体输出"更适合重构场景**：重构时具体输出可能合法地改变，而不变量不应改变。

**机制要点**：

- **生成器**：按类型生成随机输入，包含边界值（空、极大、负数、Unicode）
- **收缩**：失败后自动最小化反例
- **种子记录**：失败必须可复现，必须记录随机种子
- **与示例测试的关系**：**互补**。属性测试擅长发现**未知边界**，示例测试擅长锁定**已知行为**（回归）

## 边界：它不是什么

- **与单元测试的区别**：量词不同（全称 vs 存在）。两者是互补的两类工具。
- **与模糊测试的区别**：fuzz 关注**是否崩溃**；属性测试关注**断言的性质是否成立**，且有收缩机制。
- **与形式化验证的区别**：属性测试是**抽样，不是证明**。通过不代表对所有输入成立。

## 常见误解

1. **属性测试可以替代示例测试** → 互补。属性测试找到的反例应当固化为示例测试（回归）。
2. **随机测试不稳定** → 有种子就可复现，且失败会收缩到最小反例。
3. **它只能测简单函数** → 复杂系统也可用，但生成器编写成本会上升。
4. **通过了就说明性质成立** → 只是没找到反例。这是抽样的本性。

## 应用场景

- **该用**：纯函数、序列化与反序列化、解析器、编码解码、数据结构实现、**重构前后的等价性验证**
- **不该用**：输入难以生成、性质写不出来、外部依赖密集
- **判断依据**：先问"**这个模块有什么性质，无论输入如何都该成立？**" 写不出来，属性测试用不上
