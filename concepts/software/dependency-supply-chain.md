## 一句话定义

**中文**：管理第三方代码从来源到构建产物全过程的可信性——因为你交付的东西里有一大半不是你自己写的。

**English**: Managing the trustworthiness of third-party code from source to artifact, since most of what you ship was not written by you.

## 我的理解

**供应链攻击的结构是不对称的：攻击者只需在你依赖链的某一环成功一次，而你需要在每一环上都做对。**

这个不对称性决定了策略：**不可能"审核所有依赖"，只能分层设防并缩小爆炸半径**——来源可验证、构建可复现、产物可追溯、依赖可收敛。

最实用的一条判断：**问"如果这个依赖被替换成恶意版本，我多久能发现？"** 大多数项目的诚实答案是"直到出事"。所以工作重点不是"审完所有代码"，而是缩短这个时间差：

- 锁定到**不可变标识**（版本 + 摘要），这样"被替换"会在安装时立刻失败
- 引入新依赖时有审查动作，而不是自动接受
- 构建产物可追溯（能回答"这个制品来自哪个提交、哪次构建"）

与[可复现构建](reproducible-build.md)的关系值得说清：可复现是**验证手段**（相同的输入产出相同字节，因此能验证产物没有被改），供应链安全是**目标**。前者是后者最重要的基础设施，但不是全部——来源审查、权限收敛、运行时限制都不在"可复现"的射程内。

## 核心机制

**攻击面**：

| 环节 | 攻击形态 |
|---|---|
| 包仓库与账号 | 维护者账号被劫持、发布恶意版本 |
| 命名 | 依赖名混淆（拼写相近、AI 编造的包名） |
| 传递依赖 | 你信任 A，A 信任 B，B 出问题 |
| 构建环境 | CI 被污染、构建脚本执行任意代码 |
| 分发 | 镜像或制品仓库被替换 |

**分层对策**：

1. **来源层**：锁定版本并**校验摘要**；不使用浮动版本；优先使用有维护迹象的包
2. **构建层**：可复现构建、构建环境隔离、CI 权限最小化、构建脚本的审查
3. **产物层**：产物签名与溯源证明（SLSA 的分级思路就是这个）
4. **运行层**：最小依赖、出网限制、运行时权限收敛

**SLSA 的分级思路值得单独记**：它**不要求一次达标**，而是从"有构建文档"逐级到"构建过程可验证且不可篡改"。分级的意义在于——**它承认现实：不可能一步做完美，但可以让每一步都比上一步更难被攻破。**

**依赖收敛**：直接依赖容易审，**传递依赖的数量才是真实风险面**。所以"引入一个依赖"是一次信任转移，而不是一次功能采购——**依赖越少，攻击面越小**，这是选型的成本项，不是免费的。

**可执行动作**：依赖漏洞扫描（已知问题）、SBOM（记录你到底带了什么）、CI 里的锁定校验、新依赖引入的审查清单（是否必要、维护活跃度、是否需要写入权限）。

## 边界：它不是什么

- **与[可复现构建](reproducible-build.md)的区别**：可复现回答"**这一版到底是什么**"，供应链回答"**这些东西可信吗**"。前者是后者的手段之一。
- **与漏洞管理的区别**：漏洞扫描找的是**已知的坏代码**；供应链防护针对的是**未知的恶意注入**（包括合法包里的恶意提交）。**两者都要，不能互相替代**——只扫漏洞的项目对"从未被披露的恶意版本"毫无防护。
- **与[代码审查](code-review.md)的区别**：审查你写的代码，管不到第三方包内部。**别人的代码只能靠来源与构建链来约束。**
- **与锁定版本的关系**：锁定版本防的是"意外升级"，**防不住"这个版本本身就是恶意的"**——后者要靠摘要校验与溯源。

## 常见误解

1. **锁定了版本就安全** → 版本号是可变的标签；锁到摘要才防得住"同一版本被替换"。
2. **只需要关注直接依赖** → 传递依赖才是数量大头，也是多数实际事件的发生处。
3. **依赖越多功能越全** → 每个依赖都是一份信任转移，也是未来的升级负担。
4. **有了扫描工具就有了供应链安全** → 工具查已知漏洞，不查来源可信度与构建链完整性。
5. **私有仓库里的内部包天然可信** → 内部包的构建脚本同样在 CI 里执行，权限往往更大。

## 应用场景

- **该做**：任何发布制品（库、镜像、二进制、插件）的项目
- **判断依据**：问三个问题——**产物能不能追溯到源码提交与构建过程**？依赖是否锁定到**不可变标识**（摘要而非版本号）？新依赖的引入有没有审查动作？三问答不上，供应链就是零防护
- **配套**：CI 中做依赖审查与锁定校验、构建产物签名、限制 CI 的出网与凭据权限（这是"缩小爆炸半径"最直接的一步）
