## 一句话定义

**中文**：把基础设施的定义写成纳入版本控制的代码，使它可评审、可回滚、可重建。

**English**: Expressing infrastructure in version-controlled code so it can be reviewed, reverted, and rebuilt.

## 我的理解

**关键价值不是"自动化"，而是"可重建"。**

自动化的收益容易看到，但真正改变性质的是另一件事：**能不能在一个空账号里，用仓库里的定义把整套环境重建出来。** 能，就说明基础设施的**真实来源是代码**；不能，说明真实来源是"某台机器上的当前状态"——而那种状态无法评审、无法回滚、也无法在灾难后恢复。

由此推出三条：

1. **手工改动（点控制台）是漂移的唯一来源。** 只要允许它，代码定义与线上状态就会分叉，而下一次 apply 可能把你的手工改动**静默抹掉**——或者更糟，因为状态不一致而做出意料之外的动作。
2. **声明式优于命令式**（就基础设施而言）：声明"我要什么"，让工具算出"要做什么"，才可能有 plan/评审这一步。命令式脚本执行的是过程，重复执行的结果取决于当前状态，难以预测。
3. **状态文件是这个范式的核心复杂点。** 它记录"工具认为世界是什么样"。它需要被安全存放（常含敏感值）、被共享（团队协作）、被锁定（防并发 apply 互相踩踏）——**这三件事配错任何一个，都会出现难以推理的故障。**

## 核心机制

**基本工作流**：描述期望状态 → **生成计划（plan）** → 评审 → 应用（apply）。

**plan 这一步是这套方法最重要的安全阀**：它把"我将要做哪些改动"变成可评审的产物。跳过 plan 直接 apply，等于放弃了它相对脚本的唯一优势。

**幂等 apply**：同一份定义重复执行的结果应当一致。这是它能被放进 CI 的前提——**不可幂等的定义会让每次执行都变成一次不可预料的变更**。

**漂移检测**：定期对比"定义"与"实际状态"，把差异当作**需要处理的事件**，而不是容忍的常态。漂移本身不会立刻出问题，它的问题是**让下一次变更的结果不可预测**。

**状态与密钥的纪律**：

| 项 | 要求 | 原因 |
|---|---|---|
| 状态文件 | 加密存储、访问受限、启用锁 | 含资源细节与敏感值；并发写会损坏 |
| 凭据 | 通过注入而非写进代码或状态 | 状态会被读取、备份、共享 |
| 模块化 | 按环境/职责拆分，参数化差异 | 一份巨型定义无法局部评审 |

**环境差异怎么处理**：用**同一份定义 + 不同的参数**，而不是复制两份定义。复制会立刻分叉——**这与代码里"不要复制粘贴"是同一条理由**。

**它与其他自动化手段的边界**：配置管理工具（应用配置、软件安装）与 IaC（资源生命周期）常被混用。判断标准是——**改动的对象是"资源的存在与属性"，还是"机器内部的状态"**。

## 边界：它不是什么

- **与[配置管理](configuration-management.md)的区别**：IaC 管**资源本身**（网络、机器、数据库实例、权限策略），配置管理管**应用与环境的参数**。两者都会遇到漂移，但一个管"有什么"，一个管"怎么跑"。
- **与脚本化的区别**：脚本可以是命令式的、不可幂等的、没有 plan 的。**有脚本不等于有 IaC**——后者的关键是"期望状态 + 可评审的差异"。
- **与[可复现构建](reproducible-build.md)的区别**：可复现构建针对**制品**（同样的源码产出同样的字节），IaC 针对**环境**（同样的定义产出同样的基础设施）。两者是同一种纪律在不同对象上的应用。
- **与"全自动运维"的区别**：IaC 让环境可重建，不承诺"不需要人判断"。故障时的取舍仍然是人做的。

## 常见误解

1. **用了 IaC 工具就等于基础设施受控** → 只要控制台还能手工改，漂移就存在。
2. **状态文件可以放在开发机上** → 它需要共享、锁定与访问控制，放入个人机器必然出问题。
3. **apply 可以跳过 plan** → 放弃了唯一的评审点，工具退化成不可预料的脚本。
4. **每个环境复制一份定义更清晰** → 复制必然分叉，应共用定义、参数化差异。
5. **漂移只是"有人手动改了一下"，不影响** → 它会让下一次变更的结果不可预测，是最难排查的一类事故来源。

## 应用场景

- **该做**：任何超过一台机器的环境；有合规与审计要求的组织
- **判断依据**：问一个可验证的问题——**能在一个空账号里，只用仓库里的定义把环境重建出来吗？** 能，说明代码是真实来源；不能，说明真实来源在别处
- **配套**：plan 纳入评审流程；状态加密与加锁；定期漂移检测；凭据通过注入而非硬编码
