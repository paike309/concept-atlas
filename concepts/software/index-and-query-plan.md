## 一句话定义

**中文**：索引是让数据库不必扫描整张表就能定位数据的辅助结构；查询计划是数据库为一条具体查询选定的执行方式。

**English**: An index is an auxiliary structure that lets the database locate rows without scanning the whole table; a query plan is the execution strategy the database chooses for a specific query.

## 我的理解

**索引的收益和代价是同一件东西的两面**：它让读变快，代价是每次写入都要多维护一棵树，以及额外的存储。所以"给常用列都加上索引"不是优化，而是**把成本从读搬到写**——只有在读远多于写、且这些读确实被索引加速时才划算。

两条更硬的判断：

1. **判断索引该不该建，要问"它支撑哪一条具体查询"**，而不是"这一列经常出现在条件里"。同一条查询换一种写法，同一棵索引可能就失效了。
2. **查询计划是索引是否生效的唯一证据。** 加了索引但查询写法用不上（对列做函数运算、类型不匹配、前导通配匹配）是最常见的空欢喜——**索引存在和索引被用是两件事**。

所以调试顺序是固定的：**先看计划，再改写法，最后才考虑加索引。** 反过来做，就是在猜。

## 核心机制

**常见索引结构与适用场景**：

| 结构 | 支撑的检索 |
|---|---|
| B-tree | 等值、范围、排序（默认类型，绝大多数场景） |
| 哈希 | 仅等值 |
| GIN / GiST | 全文检索、数组、几何、包含关系 |

**复合索引的最左前缀**：索引建在 `(a, b, c)` 上时，它能支撑按 `a`、按 `a+b`、按 `a+b+c` 的检索，**但不能单独支撑按 `b` 或 `c`**。所以复合索引的列顺序由查询模式决定，不是按"重要程度"排。

**回表与覆盖索引**：如果查询需要的列全在索引里，数据库可以只读索引、不回主表（PostgreSQL 的 index-only scan）。这是把"多一个索引"变成净收益的常见手法。

**区分度（选择性）**：取值种类多、重复少的列做索引收益大；只有几位取值的列（状态、性别）单独建索引往往意义有限——扫索引再回表可能比直接全表扫更慢。

**查询计划里要看的东西**：

| 看什么 | 说明 |
|---|---|
| 扫描方式 | 全表扫描 / 索引扫描 / 位图扫描 / 索引专用扫描 |
| 预估行数 vs 实际行数 | 相差悬殊说明统计信息过时，优化器在错误前提上做选择 |
| 耗时最集中的那一步 | 优化目标是消除这一步，不是让全文更漂亮 |

**代价模型依赖统计信息**：数据库靠统计信息估算选择率。统计过期会让它在"错误的地图上"选路——所以定期更新统计（`ANALYZE`）是索引之外的另一半工作。

## 边界：它不是什么

- **与主键 / 唯一约束的区别**：唯一约束**靠索引实现**，但语义是约束不是加速。反过来说，为了加约束而建的索引不能当作性能设计的一部分，反之亦然。
- **与缓存的区别**：索引减少"每次要读多少数据"，缓存减少"要读多少次"。两者叠加，不能互相替代——**缓存挡不住全表扫描的代价，索引也不能代替缓存挡住重复查询**。
- **与分区的区别**：分区是把一张大表按规则切成多张（可裁剪扫描范围），索引是在一张表内加速定位。分区能减少扫描的数据量，但不是索引的替代品，反之亦然。
- **与"优化器"的区别**：查询计划是优化器的**输出**，索引、统计信息、查询写法是它的**输入**。抱怨"优化器选错了"之前，先确认输入是否合理。

## 常见误解

1. **索引越多查询越快** → 写入变慢、存储变多、优化器的选择空间也变大，反而可能选错。
2. **建了索引就一定会用** → 列被函数包装、类型不匹配、前导通配、返回行占比过高，都会让它不被选中。
3. **复合索引里的每一列都能单独用** → 最左前缀，跳不过前面的列。
4. **EXPLAIN 里的代价数字是耗时** → 它是优化器的相对估算单位，**跨查询、跨机器不可直接比较**。
5. **只要慢就加索引** → 慢可能来自锁等待、连接数、数据量、N+1 查询。**先定位，再动手。**

## 应用场景

- **该建**：高频出现在条件、连接、排序中，且区分度高、该表写入不密集的列
- **不该建**：写多读少的表、低区分度列、很少被查询路径用到的列
- **判断依据**：拿一条**真实**查询，看它扫了多少行、返回了多少行——扫描量远大于返回量时，索引才有意义
- **上线纪律**：在生产库建索引可能长时间占用 IO、甚至阻塞写入。动手前先确认所用数据库支持哪种在线建索引方式，并放在低峰期
