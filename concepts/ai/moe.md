## 一句话定义

**中文**：把 Transformer 中的前馈层替换为多个"专家"加一个路由器，每个 token 只激活其中少数几个。

**English**: Replacing the feed-forward layer with several expert subnetworks plus a router, activating only a few experts per token.

## 我的理解

它解决的是**参数量与计算量的解绑**。

传统结构里，参数量增加必然带来计算量增加。MoE 让两者可以分开调节：总参数（容量、知识存储）可以很大，而每个 token 的计算量（FLOPs）保持在较低水平。

**但"更便宜"只对推理算力成立**，代价在别处：

| 代价 | 原因 |
|---|---|
| 显存不降反升 | 所有专家都要加载 |
| 训练不稳定 | 路由器容易坍缩，把大多数 token 发给少数专家 |
| 批处理效率下降 | 不同 token 走不同专家，调度开销上升 |
| 分布式通信重 | 专家分布在不同设备，token 需跨设备路由 |
| 微调更难 | 稀疏激活使部分专家得不到更新 |

## 核心机制

- **路由**：对每个 token 计算到各专家的得分，取 top-k（$k$ 通常 1~2）
- **负载均衡损失**：训练时加惩罚项，避免少数专家过载、其余闲置
- **容量与溢出**：每个专家有容量上限，超出的 token 被丢弃或走残差路径
- **专家并行**：专家分片到不同设备，**跨设备通信是主要瓶颈**
- **与传统前馈层的换算**：一个 MoE 层 ≈ 多个前馈层的参数 + 一个路由器的计算

## 边界：它不是什么

- **与模型集成的区别**：集成是多个完整模型各自出结果再投票；MoE 是**单个模型内部**的稀疏子网络，输出只有一条路径。
- **与[多头注意力](multi-head-attention.md)的区别**：多头在特征维度并行且**全部激活**；MoE 在参数维度**稀疏激活**。两者正交。
- **与知识蒸馏的区别**：蒸馏压缩参数量，MoE 扩张参数量、压缩每 token 计算量。

## 常见误解

1. **MoE 省显存** → 省的是**算力**，显存需求更高。
2. **专家真的对应可解释的领域** → 路由学到的分工不保证对应人类可理解的类别。
3. **专家越多越好** → 路由难度、负载均衡成本、通信开销都随专家数上升。
4. **MoE 训练更容易** → 恰恰更难，路由坍缩是常见失败模式。

## 应用场景

- **该用**：算力受限但需要大容量；服务吞吐高；有分布式训练条件
- **不该用**：单卡部署、显存紧张、微调频繁
- **判断依据**：先算清两笔账——**每 token 计算量**（MoE 的优势）与**总参数显存**（MoE 的成本）。只有前者是瓶颈时才值得
