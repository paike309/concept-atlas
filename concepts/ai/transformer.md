## 一句话定义

**中文**：一种完全用注意力（加前馈层、残差、层归一化）堆叠起来的序列建模架构，抛弃了循环结构，因此可以在序列维度上并行训练。

**English**: A sequence modeling architecture built by stacking self-attention, position-wise feed-forward layers, residual connections and layer normalization — with no recurrence, so training parallelizes across sequence positions.

## 我的理解

它的核心贡献不是"注意力"这个算子，而是**把顺序依赖从计算图里去掉了**。RNN 必须算完第 $t$ 步才能算第 $t+1$ 步，序列长度直接等于串行步数，GPU 的并行度被浪费掉。Transformer 让所有位置同时算，代价是位置信息需要**另行注入**（位置编码）——它自己不知道谁在前谁在后。

所以可以这样记：**用并行换掉了顺序信息，再花钱把顺序信息买回来**。

这也是后面所有麻烦的来源：为了让"买回来的位置信息"能覆盖更长范围，才会出现位置编码外推、长上下文这些议题（见 [上下文窗口](context-window.md)）。

## 核心机制

**一个编码器块**（原始论文里重复 6 次）：

1. 多头自注意力（见 [注意力机制](attention-mechanism.md)）
2. 残差连接 + 层归一化
3. 逐位置前馈网络（两层 MLP，中间维度通常放大 4 倍）
4. 残差连接 + 层归一化

**解码器块**多一个交叉注意力：query 来自解码器自身，key / value 来自编码器输出。这是"读原文"的通道。生成时配因果掩码，防止看到未来的 token。

**位置编码**：原论文用正弦函数，$PE_{(pos,2i)} = \sin(pos/10000^{2i/d})$，偶数维用 sin、奇数维用 cos。这样相对位移可以表达为线性变换，便于外推。现代实现多用可学习位置嵌入或 RoPE。

**三个设计选择的意义**：

- **残差连接**——让梯度能穿过几十层不被衰减，否则深度堆不上去。
- **层归一化**——稳定激活分布。放注意力之前叫 Pre-LN，之后叫 Post-LN；Pre-LN 训练更稳，是现在的默认。
- **前馈层**——按位置独立作用，不跨位置交互。参数量占整块的大部分（约 2/3）；有解释认为它承担事实知识的存储。

**成本**：注意力 $O(n^2 d)$，前馈 $O(n d^2)$。序列短时前馈占主导，序列变长后注意力项迅速超过——这是"长上下文为什么贵"的算术依据。

## 边界：它不是什么

- **与 [注意力机制](attention-mechanism.md) 的区别**：注意力是部件，Transformer 是成品结构。BERT、GPT、T5 都是 Transformer，但**用法不同**：BERT 只用编码器（双向、适合理解类任务），GPT 只用解码器（因果、适合生成），T5 编解码都用（适合转换类任务）。选型时先问"我这个任务要不要看未来"。
- **与 RNN / LSTM 的区别**：RNN 顺序处理、状态有界、长程依赖随距离衰减；Transformer 全局并行、无显式状态、长程依赖靠注意力权重直接连接。代价是显存随序列长度平方增长。
- **与 MLP-Mixer、状态空间模型（如 Mamba）的区别**：这些是"后 Transformer"方向，试图用非注意力机制拿到同等效果，复杂度压到 $O(n)$ 或 $O(n \log n)$。目前注意力在通用能力上仍是主流，但长序列场景已有替代方案在跑。

## 常见误解

1. **Transformer 就是注意力** → 注意力约占参数量的 1/3，前馈层占大头。去掉前馈层模型基本无法工作。
2. **它是"理解语言"的模型** → 它建模的是 token 共现的统计结构。所谓"理解"的程度是外部观察结论，不是架构内置的属性。
3. **层数越多越强** → 参数量、训练数据量、训练算力需要匹配。同数据量下盲目加层会欠拟合或训练不稳。
4. **编码器和解码器只是方向不同** → 差别不止方向：解码器多交叉注意力、多掩码，且生成时每步要重算（靠 KV Cache 才不至于重算全部）。

## 应用场景

- **该用**：序列长度中等、数据量充足以喂饱参数、训练算力可并行调度。文本、代码、语音、蛋白质序列、时序都适用。
- **不该直接用**：样本极少（几百条以下）且无预训练权重——此时树模型或线性/卷积模型更省；或序列极长且延迟敏感——考虑状态空间模型或检索前置。
- **工程上真正决定成败的**：不是架构本身，而是预训练权重是否匹配下游领域、以及上下文怎么组织。同一个架构，喂进去的上下文不同，效果差距远大于换架构。

## 自测

1. 去掉位置编码，一个只做自注意力的编码器还能区分"猫追狗"和"狗追猫"吗？为什么？
2. Pre-LN 和 Post-LN 的差别在哪，为什么深模型更倾向 Pre-LN？
3. 序列长度翻倍，注意力的计算量和显存各变多少？前馈层呢？据此判断什么长度区间该考虑替代方案。
