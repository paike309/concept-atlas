## 一句话定义

**中文**：在召回结果之上，用更精确也更贵的模型重新排序，取排序后的前几条。

**English**: Re-scoring a retrieved candidate set with a more accurate and more expensive model, then taking the top few.

## 我的理解

它存在的理由是**两阶段检索的成本结构**：用精确模型扫全部文档太贵，而用粗糙模型一次召回会漏。分成两阶段，就让"便宜但宽"和"贵但准"各司其职。

一条关键纪律：**召回阶段宁多勿少，精度交给重排。**

所以第一层的目标不是"排对"，而是"不漏"——评估口径也要跟着改，看召回率，不看 top-1。

**重排模型通常是交叉编码器（cross-encoder）**：把查询和文档**拼在一起**输入模型打分，而不是各自编码后算距离。代价是每一对都要跑一次模型、无法预计算，所以只能用在少量候选上。

## 核心机制

**两阶段结构**：

```
召回（向量 / 关键词）：百万 → 几百
重排（交叉编码器）：  几百 → 几条
```

| | 双编码器（召回） | 交叉编码器（重排） |
|---|---|---|
| 做法 | 各自编码，算向量距离 | 拼在一起输入模型 |
| 预计算 | 可（文档向量离线算好） | **不可** |
| 精度 | 较低 | 较高 |
| 成本 | 低 | 每对一次前向 |

这是典型的"**离线换在线**"取舍。

**候选集大小**：太小则召回不足（重排无从发挥），太大则延迟高。应按 **P95 延迟约束反推**，而不是拍一个数。

**与混合检索的分工**：混合检索解决"召回不全"，重排解决"排序不准"。**两者是不同环节，不能互相替代。**

## 边界：它不是什么

- **与[向量检索](vector-search.md)的区别**：召回 vs 精排。前者追求不漏，后者追求准。
- **与规则排序的区别**：规则可解释、可控，但难以覆盖语义相关性。
- **与"用大模型逐条打分"的区别**：原理相近但成本更高（大模型远重于重排模型），通常只在候选极少时使用。

## 常见误解

1. **重排能救回没召回的内容** → **不能**。召回没拿到的文档，重排根本看不到。这就是"召回优先"的原因。
2. **重排模型越大越好** → 延迟成倍增长，且收益递减。
3. **有了重排就不用混合检索** → 两者解决不同问题：一个补召回，一个改排序。
4. **把重排当召回用** → 对全量文档做交叉编码，延迟会直接爆炸。

## 应用场景

- **该用**：候选集大、精度要求高、延迟允许一次额外调用
- **不该用**：候选本来就少（直接排序即可）、延迟极敏感
- **判断依据**：先测**召回率**。如果正确文档根本不在候选集里，加多好的重排都没用
