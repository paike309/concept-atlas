## 一句话定义

**中文**：把离散的词元 ID 映射为连续向量的可学习参数表，向量之间的位置关系编码了共现统计上的相似性。

**English**: A learnable lookup table mapping discrete token IDs to continuous vectors, where relative positions encode similarity in co-occurrence statistics.

## 我的理解

分词把文本变成了 ID，但 **ID 只是序号，不含任何含义**——ID 42 和 ID 43 之间不存在"相近"这回事。嵌入层做的事是**给每个 ID 分配一个坐标**，于是"相近"变成可计算的东西。

这是模型里唯一直接学"词义"的地方，后面所有层都在操作这些向量的组合。

一个有用的直觉检验：如果两个词的向量方向接近，模型在它们之间迁移会更省力。所谓的"语义算术"（king − man + woman ≈ queen）就是这种几何结构的直接产物——**它是线性空间的性质，不是推理能力**。

## 核心机制

**形状与查表**：参数矩阵是「词表大小 × 向量维度」（例：50000 × 4096）。输入 ID 序列取出对应行，得到「序列长度 × 维度」的矩阵。**这是纯索引操作，没有计算。**

**训练**：没有额外标签，靠"预测下一个词"这个目标通过反向传播把语义相近的词推到相近位置。向量含义是训练逼出来的副产物。

**几个设计点**：

| 点 | 说明 |
|---|---|
| 维度选择 | 太小表达能力不足，太大参数浪费且更难训练；常见几百到上万 |
| 权重共享 | 很多模型输出层复用同一矩阵，减少参数并让输入输出空间一致 |
| 位置信息 | **不在这里**。嵌入只编码"是什么词"，不编码"在第几位"，后者由位置编码负责 |

## 边界：它不是什么

- **与 [分词](tokenization.md) 的区别**：分词决定"切成什么单位"（离散），嵌入决定"单位变成什么坐标"（连续）。中间只隔一层查表，但性质完全不同。
- **与向量数据库里的 embedding 的区别**：名字相同，用途不同。**这里的是模型内部的输入层参数**，参与训练；**向量库里的 embedding 是文档的外部表示**，通常由另一个模型生成，不参与当前模型的训练。混谈会导致"换个整体模型但检索库没换"这类错误。
- **与"语义理解"的区别**：向量相近只反映**共现统计**相近。模型并不因此知道"医生"和"护士"的职业差异——它只知道这两个词常出现在相似上下文里。

## 常见误解

1. **嵌入是人工设计的语义空间** → 没有任何人工定义维度含义。想解释某一维代表什么，通常是事后附会。
2. **向量距离可以直接当语义相似度** → 模型内部基本成立；外部检索场景常需专门的对比学习目标才可靠，直接用原始嵌入做检索往往不理想。
3. **换嵌入模型只是换个工具** → 不同模型的向量空间不可混用，同一个库里混两种来源会导致检索结果错乱。
4. **语义算术说明模型会推理** → 它是线性结构的几何性质，不能推广到复杂推理。

## 应用场景

- **该关注**：做检索、聚类、去重、多语言对齐；排查"语义相近但结果不对"的问题
- **不必深究**：只做文本生成时，知道"嵌入把词变成向量"就够
- **判断依据**：当你需要"按意思而不是按字符串"匹配内容时，才会真正碰到嵌入的质量问题
