## 一句话定义

**中文**：通过组织输入文本来引导模型输出的方法集合。它改变的是这一次调用的上下文，不是模型权重。

**English**: The set of practices for organizing input text to steer model output — changing the context of a single call, not the model's weights.

## 我的理解

提示工程被讲成一堆"咒语"，这是误读。它的本质是**信息与约束的组织**：

模型每次前向只能看到你给它的上下文（见 [上下文窗口](context-window.md)），它能做出的推理完全取决于上下文里有什么、以什么形式给出。所以有效的提示词只做三件事——**补齐缺失信息、明确输出契约、给出判断依据**（示例或规则）。

凡是"技巧"都有失效条件，理解失效条件比记住技巧重要。举例：逐步推理在需要多步计算的任务上有效，在简单的信息抽取任务上只是白烧 token。

## 核心机制

**提示的四个组成**（按信息密度从高到低）：

1. **任务描述**——要做什么，判断标准是什么
2. **输入数据**——待处理的内容，必须与指令在结构上分开
3. **输出格式约束**——要程序消费就必须可解析
4. **示例**——少样本示范

**少样本示例的真实作用**：不是"教模型新知识"，而是**指定映射关系与输出风格**，把任务从"理解"降级为"模仿"。理解这一点就能判断示例该怎么给——给边界情形比给典型情形更有效。

**思维链（CoT）为什么有效**：它把隐式计算变成上下文里的显式 token。推理步骤一旦写进上下文，就成为后续 token 的条件。所以诱发方式不限于"让我们一步步思考"——给一个含推理步骤的示例同样有效，而且更稳。

**结构分隔的价值**：用 XML 标签、Markdown 标题把"我的指令"和"待处理数据"明确标出。这既减少歧义，也直接关系到提示注入防御——未分隔的数据会被模型当成指令。

**顺序效应**：关键信息放在开头或结尾利用率最高，中间最容易被忽略（见《Lost in the Middle》）。

## 边界：它不是什么

- **与训练（微调）的区别**：提示改输入，即时生效、可回滚、可逐条追溯；微调改权重，需要重训。需要"稳定且不可绕过的行为"时，提示不是合适工具。
- **与角色扮演的区别**：设定角色只给模型一个语气与视角的先验，不赋予任何新能力或权限。"你现在是资深安全审计员"不会让模型真的具备审计能力。
- **与 [RAG](rag.md) 的区别**：RAG 解决"材料从哪来"，提示工程解决"材料怎么组织给它"。两者互补，不能互相替代。

## 常见误解

1. **提示词是玄学，只能靠试** → 大部分效果差异来自信息是否补齐、格式是否明确。把这两件事做好，试错量会显著下降。
2. **越长的提示越好** → 无关内容既稀释关键信息，又引入注入风险。
3. **加一句"你是世界顶级专家"能提升能力** → 改变的是语气与先验，不是能力上限。
4. **提示工程会随模型进化被淘汰** → 该淘汰的是"补偿模型缺陷的技巧"（强制格式的咒语）；"明确任务与输出契约"这部分会一直存在。

## 应用场景

- **该做**：输入结构固定（有明确字段）、输出要被程序解析、任务有可写下来的判断标准
- **不该做**：把复杂业务规则堆进提示词去实现——那应该写成代码或工具
- **判断依据**：如果一段提示词超过两屏，先问"这里哪些应该由模型判断，哪些应该由代码判断"
