## 一句话定义

**中文**：把文本切成词表里已有的最小单位（词元 token），并映射成整数 ID 的过程——模型能看见的只有这些 ID。

**English**: The process of splitting text into the discrete units (tokens) present in a fixed vocabulary and mapping them to integer IDs — the only form of input a language model actually sees.

## 我的理解

分词是"文本世界"和"向量世界"之间唯一的一道门。门怎么开，决定了模型的全部先天限制。

这一点很容易被低估：模型数不清字母、拼不出罕见词、对空格敏感、中文比英文费 token——**这些不是模型"笨"，是分词器造成的**。字母在切分阶段就被合并进了同一个 token，模型根本没有机会看见 token 内部的字符。要理解模型的任何字符级怪癖，先看分词器。

## 核心机制

**为什么是子词（subword）而不是词或字符**：

- 切到词：词表爆炸（含拼写变体、专名、代码标识符），且永远有未登录词
- 切到字符：序列长度爆炸，注意力成本随长度平方增长（见 [注意力机制](attention-mechanism.md)）
- 子词是折中：常见词保留为整体，罕见词拆成常见片段

**BPE 的直觉**：从最小单元开始，统计相邻对的出现频率，把最高频的一对合并成新单元，重复到达到目标词表规模。高频片段自然成为独立 token，低频词自动被拆碎。

**"最小单元"是什么，取决于分词器的选择**：从字符出发（如原论文），或从**字节**出发（byte-level BPE，GPT-2 之后的主流）。字节级的好处是任何 Unicode 文本都能表示，理论上不会出现"未登录词"；代价是汉字这类多字节字符会被拆成字节级片段，除非合并表里已经学出了对应的整字片段——这也解释了为什么词表构成会直接影响中文的 token 消耗。

**数量级**：

- 主流词表规模 3 万 ~ 15 万
- 英文：1 token ≈ 4 字符 ≈ 0.75 个单词
- 中文：1 个汉字通常占 1 ~ 2 个 token，具体取决于词表的训练语料构成
- **表达同一含义时**，中文所需的 token 数常是英文的 1.5 ~ 2 倍（因为多数词表的训练语料以英文为主）

**特殊 token**：起始/结束标记、填充位、对话角色标记、工具调用标记。它们不来自文本，是训练时人为加进词表的控制符号。

## 边界：它不是什么

- **与词嵌入（Embedding）的区别**：分词决定"把文本切成什么单位"（离散、整数 ID）；词嵌入决定"每个单位变成什么向量"（连续）。分词在前，嵌入在后。顺序颠倒的常见后果是把"词表大小"和"向量维度"混为一谈。
- **与字符、字节的区别**：模型处理的既不是字符也不是字节，是词表里的子词单元。所以"strawberry 里有几个 r"这类任务出错，属于结构性限制而非知识缺陷。
- **与语言学分词的区别**：没有词性、没有句法，纯粹是统计压缩。中文分词工具做的事（按词典和语法切词）和这里的 tokenization 不是同一件事，虽然中文名相同。

## 常见误解

1. **一个英文单词等于一个 token** → 常见词通常是一个，罕见词、拼写错误、代码标识符会被拆成多段。同一个词在不同上下文里也可能被切成不同片段。
2. **中文和英文一样费 token** → 多数词表以英文语料为主训练，中文更费。这直接影响按 token 计费的成本、上下文能装多少内容。
3. **换个更好的分词器就能提升模型** → 词表与权重是绑定的，换词表等于换输入空间，模型必须重训。
4. **空格不重要** → 空格常参与 token 组成（`" hello"` 与 `"hello"` 是不同 token）。这直接解释了很多补全、缩进、代码生成的行为差异。

## 应用场景

- **该关注**：估算成本与上下文占用、做长文档分块、排查字符级错误（多一个字母、少一个空格、算术出错）、对比中英文材料的成本
- **不必深究**：只用 API 做常规任务时，知道"按 token 计价"和"中英密度不同"就够了
- **判断依据**：出现字符级错误时，先怀疑分词，再怀疑模型能力
