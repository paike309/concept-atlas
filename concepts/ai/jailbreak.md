## 一句话定义

**中文**：通过构造特殊输入绕过模型自身的安全策略，使其产出本应拒绝的内容或执行本应拒绝的动作。

**English**: Crafting inputs that bypass a model's own safety policy, producing content or actions it should refuse.

## 我的理解

先把最容易混的一对概念分清：

| | 越狱 Jailbreak | 提示注入 Prompt Injection |
|---|---|---|
| 攻击对象 | **模型的安全策略** | **应用的信任边界** |
| 本质 | 与训练成果对抗 | 利用"外部数据被当成指令"的结构缺陷 |
| 修在哪 | 模型侧（对齐、护栏） | 应用侧（权限、校验、确认） |

两者都表现为"模型做了不该做的事"，**但修法完全不同**。把两者混为一谈，会导致在错误的层面做防御。

**越狱手法的共同本质**是**改变问题的框架**：让它看起来不像一个请求（虚构场景、角色扮演、编码混淆、分步拆解、多语言混排）。理解这一点就能理解为什么"加一句'不要越狱'"没用——**它在字面层面防守，而攻击在框架层面进行。**

实践上更重要的一条：**越狱成功的概率永远不为零。**

所以真正的边界必须在应用侧——权限、确认点、输出校验。这与[提示注入防御](../agent/prompt-injection-defense.md)的结论一致。

## 核心机制

**手法分类**：

| 类型 | 说明 |
|---|---|
| 角色扮演与虚构框架 | "我们在写小说，角色会说……" |
| 编码与混淆 | Base64、零宽字符、多语言混排 |
| 分步引导 | 把有害目标拆成多个看似无害的步骤 |
| 上下文投毒 | 先建立错误前提，再提出请求 |
| 长上下文稀释 | 把恶意请求埋在中段 |

**防御层次**（从强到弱）：训练期对齐 → 推理期护栏 → 输出侧过滤 → **应用侧权限与确认**。

**红队测试**：系统化构造尝试，记录成功率与绕过模式，**形成回归集**。这一步的关键是把"偶尔发现的绕过"变成"可重复检验的问题"——否则修复无法验证。

## 边界：它不是什么

- **与[提示注入](../agent/prompt-injection-defense.md)的区别**：见上表。这是本卡最重要的边界面。
- **与内容审核的区别**：审核在**输出侧**过滤已生成的内容；越狱防御影响的是**是否产出**。
- **与"能力限制"的区别**：**直接不提供能力**比任何对齐手段都可靠。有些能力的最优防御就是不存在。

## 常见误解

1. **强模型不会被越狱** → 成功率降低但不为零。
2. **加了系统提示就安全** → 提示是概率约束。
3. **越狱只影响内容输出** → 也会导致工具被滥用、数据被外泄。
4. **知道手法就能防住** → 手法可以无限组合，防御需要覆盖全部表述。

## 应用场景

- **该做**：任何面向用户、能触发动作的系统都要做红队测试并保留回归集
- **判断依据**：问"**如果模型被越狱，它能做的动作里哪些是不可逆的？**" 那些必须由应用侧拦住，不能指望模型不越狱
- **不该做**：把安全责任全部放在模型侧
