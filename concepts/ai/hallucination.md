## 一句话定义

**中文**：模型生成流畅、自信、但事实错误或无依据的内容。

**English**: Fluent, confident output that is factually wrong or unsupported by any source.

## 我的理解

幻觉不是"模型撒谎"，也不是训练不足。它有**结构性根源**：

预训练目标是预测下一个 token，**这个目标从不要求输出为真**（见[预训练与自监督目标](pretraining.md)）。

于是机制清楚了：**概率上最连贯的续写，与事实上的正确，是两件不同的事。** 当模型缺知识时，它不会"知道自己不知道"，而是生成在语言上最像答案的东西。

由此推出两条实践结论：

1. **模型对自己是否确定没有可靠的自省。** 让它自评置信度通常无效——它会自信地给错误答案打高分。
2. **降低幻觉的手段都是"外部约束"**——检索、要求引用、限定在给定材料内作答。指望通过提示让它"更诚实"，只能有限改善。

还有一类是**忠实性**问题：材料里有正确信息，模型仍然偏离它。这在 RAG 系统里最致命——**有材料却没被遵守**，且从输出看不出来。

## 核心机制

**三类成因**：

| 成因 | 说明 |
|---|---|
| 知识缺失 | 最常见。模型不知道，但生成最像答案的内容 |
| 训练数据错误与冲突 | 学到的事实本身有误或互相矛盾；过时信息尤其常见 |
| 解码与上下文因素 | 采样温度、上下文里的错误前提、被迫满足的格式要求 |

**缓解手段与各自的代价**：

| 手段 | 效果 | 代价 |
|---|---|---|
| RAG | 明显降低 | 依赖检索质量；检索错则幻觉更"有据可依" |
| 要求标注出处 | 让偏离更容易被发现 | 不能消除，且模型可能编造出处 |
| 明确允许"不知道" | 减少硬答 | 必须写进提示，否则模型倾向硬答 |
| 降低温度 | 减少低概率错误 | 不改变分布中心，缺失的知识仍然缺 |
| 外部校验（计算器、数据库） | 对可验证类型最有效 | 需要工具与额外工程 |

## 边界：它不是什么

- **与"错误"的区别**：错误可以是算错、格式错；幻觉特指**编造了没有依据的内容**——编造引用、编造 API、编造事件。
- **与创造性生成的区别**：写故事时"编"是功能，报事实时才是缺陷。**区分标准是任务是否要求忠实。**
- **与知识截止日期的区别**：截止日期导致"不知道新事"；幻觉是"不知道却给出确定答案"。前者是能力边界，后者是行为缺陷。

## 常见误解

1. **模型更强就没幻觉了** → 规模降低部分事实错误，但不消除结构性成因。
2. **加一句"不要编造"就能解决** → 有限改善，不能替代外部约束。
3. **模型说得很肯定所以是对的** → **表述确定性与事实正确性不相关。**
4. **上了 RAG 就没有幻觉了** → 只降低。检索失败、材料错误、不忠于材料三种情况都在。

## 应用场景

- **必须重点防**：事实查询、法律医疗金融、代码与 API 生成、引用文献
- **可容忍**：头脑风暴、草稿、创意写作
- **判断依据**：问"**如果这一句是错的，代价是什么**"。代价高就必须有外部校验环节，不能只靠提示
- **排查顺序**：先看材料是否检索到（检索问题），再看材料是否被遵守（忠实性问题），最后才怀疑模型知识
