## 一句话定义

**中文**：把图像转成模型可处理的向量序列的组件——本质是把二维连续信号切成可被注意力机制消费的离散单元。

**English**: The component that turns an image into a sequence of vectors a model can consume — splitting a 2-D continuous signal into units attention can operate on.

## 我的理解

**视觉编码器要解决的核心问题，和[分词](tokenization.md)是同一个问题的另一种形态：怎么把连续输入切成离散单元。**

图像与文本的差别带来三个额外难点：

1. **二维结构**：文本是一维序列，图像是二维网格。切成 patch（小块）并展平成一维序列后，**空间关系要靠[位置编码](positional-encoding.md)重新注入**——这与文本里"顺序要显式注入"是同一件事。
2. **分辨率与 token 数量的直接冲突**：切得越细，细节保留越多，但**视觉 token 数量按面积增长**。而 token 数量直接决定成本与上下文占用。**这是"高分辨率"在工程上不免费的根源。**
3. **没有天然的语义边界**：文本有词与字，图像切块是**人为的网格划分**，一个物体可能横跨四个 patch，也可能只占一个 patch 的一角。所以 patch 是"计算单元"，不是"语义单元"。

由此得到一条实用判断：**问"视觉编码器能不能看清"时，实际在问"分辨率、切块密度、以及是否动态调整分辨率"。** 固定输入尺寸的实现会先把图缩放到某个尺寸——**小字与细小差异在这个过程中可能已经被丢掉**，后面再怎么推理也补不回来。

## 核心机制

**基本流程**：切 patch → 线性投影成向量 → 加位置编码 → 送入 Transformer 编码 → 输出视觉 token 序列。

**两类主要用法**：

| 用法 | 形态 | 典型用途 |
|---|---|---|
| 双塔对比（CLIP 式） | 图像编码器与文本编码器各自独立，输出在共享空间里比对 | 检索、零样本分类、对齐 |
| 作为多模态模型的视觉前端 | 视觉编码器 + 投影层 → 接到语言模型 | 图文问答、文档理解、界面操作 |

**关键工程变量**：

| 变量 | 影响 |
|---|---|
| 输入分辨率 | 细节保留能力；**通常是先缩放再切块，缩放即信息损失** |
| patch 大小 | patch 越小细节越多、token 越多、成本越高 |
| 动态分辨率 | 支持不同长宽比与更大输入，代价是序列长度可变 |
| 视觉 token 数量 | 直接决定上下文占用与推理成本 |

**与文本 token 的比例感**：一张图经编码后可能产生数百到数千个视觉 token，**远超一句话的文本 token 数**。这解释了一个实际现象：**多模态请求的上下文占用与成本往往由图像主导**，而不是文字。

**为什么视觉编码器通常冻结**：在与语言模型拼接的方案里，视觉编码器往往**保持不训练或只做轻量适配**。这样做更省成本，也更容易复用；代价是**视觉侧的表达能力被固定在预训练时的分布上**（训练数据里少见的情形，后续很难补）。

## 边界：它不是什么

- **与[分词](tokenization.md)的区别**：都是切分连续输入，但文本的切分单元有语言学依据（子词），图像的切分是**空间网格**。因此**视觉 token 不承载"语义单位"的含义**。
- **与[跨模态对齐](cross-modal-alignment.md)的区别**：编码器负责**把图像变成向量**，对齐负责**让这个向量与文本向量落在同一空间**。一个好的视觉编码器不保证对齐成立，反之亦然。
- **与图像分类模型（只输出标签）的区别**：分类模型输出**一个类别**，视觉编码器输出**一组向量**供后续模块使用。前者是不可组合的端点，后者是组件。
- **与生成模型（如[扩散模型](diffusion-models.md)）的区别**：编码器是"读"，生成模型是"写"。两者都可以基于视觉表示，但目标相反。

## 常见误解

1. **图像是"直接"输入模型的** → 必须先编码成向量序列，**模型看到的始终是数字**。
2. **分辨率越高越好** → token 数量按面积增长，成本与上下文占用同步上升；且固定尺寸实现会先缩放。
3. **视觉编码器"理解"图像** → 它产生的是向量表示，语义判断依赖后续模块与对齐质量。
4. **视觉 token 与文本 token 等价** → 数量差距大，对上下文与成本的影响完全不同。
5. **patch 就是物体** → patch 是人为网格，与语义边界没有对应关系。

## 应用场景

- **该用**：图文检索、文档与图表理解、界面操作类 Agent、以及作为多模态模型的前端
- **判断依据**：问三句——**输入在编码前被缩放到多大**（会不会丢掉关键细节）？**一张图占多少 token**（成本与上下文是否可承受）？**视觉侧是否需要针对领域适配**（现有预训练分布是否覆盖）？
- **配套**：上下文预算要**为视觉 token 单独留额度**（见[上下文预算管理](../agent/context-budget.md)）；推理成本估算要把图像计入（见[推理成本与显存估算](inference-cost.md)）
