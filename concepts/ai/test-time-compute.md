## 一句话定义

**中文**：在推理阶段投入更多计算（更长的思考、多次采样、搜索或验证）来换取更高的准确率。

**English**: Spending more compute at inference time — longer thinking, multiple samples, search, or verification — to buy higher accuracy.

## 我的理解

**这是与"训练更大的模型"并列的第二条能力曲线。**

过去提升能力主要靠训练侧 Scaling：更多参数、更多数据、更多算力。测试时计算提供了另一条路径——**同一个模型，想得久一点就更准**。它的实际意义在于：**把成本从训练侧转移到推理侧**。

由此推出三条判断：

1. **收益高度依赖"可验证性"。** 多采样的前提是**能判断哪个答案更好**：
   - 有验证器（数学题可核对、代码可运行、约束可检查）→ 可以采样多次再筛选，收益显著
   - 没有验证器（开放式写作、主观判断）→ 只能靠模型自评，**而模型的自评不可靠**（见[幻觉](hallucination.md)）——此时多采样的收益会大幅缩水
2. **它改变的是成本结构，不是免费的提升。** 采样 n 次就是 n 倍推理成本与延迟。所以**适合低频高价值任务**（一次昂贵的研究分析），不适合高频低成本任务（每次交互都多想一遍）。
3. **它和训练侧一样存在收益递减。** 从"不想"到"想"的提升通常很大，从"想很久"到"想更久"的提升迅速变小。**投入前应当先小规模验证边际收益**，而不是假设越多越好。

## 核心机制

**四种主要形式**：

| 形式 | 做法 | 前提 |
|---|---|---|
| 长推理 | 模型生成长思维链（内建或提示） | 任务可拆步骤 |
| 多次采样 + 投票 | 采 n 次，取多数一致答案 | 答案可比较、有明确形式 |
| 采样 + 验证筛选 | 采 n 次，用验证器挑最好的 | **有验证器** |
| 搜索 | 在推理步骤层面展开与回溯 | 步骤可评估、状态可表示 |

**验证器的两类来源**：

- **外部可执行验证**：跑测试、代入求解、与数据库核对——**这类最可靠**
- **模型自评（含奖励模型）**：能筛掉明显错误，但**存在系统性偏好**（偏好更自信、更"漂亮"的答案，而它们不一定更正确）

**成本量级**：采样 n 次 → 成本与延迟约 n 倍；长推理 → 成本随之增长（输出的思考 token 也计费）。这两者可以叠加，**叠加时要重新评估是否还划得来**。

**与[采样策略](sampling.md)的区别**：温度调节的是**同一次生成的随机性**，测试时计算调节的是**总量**。**调高温度不是增加计算**——它只是让单次生成更发散，在无验证器时通常会让结果更不稳定。

**与[推理成本](inference-cost.md)的关系**：测试时计算把"每次请求便宜"换成了"每次请求贵但更准"。对容量规划的影响是**单请求成本方差变大**（简单任务与复杂任务差很多倍），因此容量与超时都要按分布设计。

## 边界：它不是什么

- **与[缩放定律](scaling-laws.md)的区别**：那是**训练侧**的幂律（参数量、数据量、训练算力），这是**推理侧**的投入产出。两者是两条不同的曲线，可以叠加，也可以互相替代——**"小模型多想"有时能顶上一个更大的模型**。
- **与"模型更大"的区别**：更大的模型提升的是**单次前向的能力上限**；测试时计算提升的是**用多次前向逼近上限**。前者成本在训练与推理双向增加，后者只在推理侧。
- **与[缓存](kv-cache.md)/[量化](quantization.md)等工程优化的区别**：它们降低**单位计算的价格**，测试时计算增加**计算量**。方向相反，可以叠加使用。
- **与"更长的提示"的区别**：更长的提示是给更多**信息**，测试时计算是给更多**计算**。信息可以降低不确定性，计算只能在已有信息下更充分地搜索。

## 常见误解

1. **想得越久越好** → 收益递减；超过某点后成本上升而准确率几乎不动。
2. **所有任务都能靠它提升** → 无验证器的开放式任务提升有限，且可能因自评偏差而非一致变差。
3. **提高温度就等于增加计算** → 温度是随机性，不是计算量。
4. **采样多次必然更准** → 只有在能可靠比较候选答案时成立。
5. **模型自评足以当验证器** → 它有系统性偏好，不能替代外部可执行验证。

## 应用场景

- **该用**：数学与形式化推理、代码生成（测试即验证器）、有明确约束的规划问题、低频高价值的分析任务
- **不该用**：高频低价值交互、延迟敏感场景、答案无法比较的开放式创作
- **判断依据**：先回答两句——**我有没有一个可用的验证器**？**这个任务的价值能否覆盖数倍成本**？再小规模实测边际收益
- **配套**：把采样次数与验证结果纳入[评估](evaluation.md)（否则无法判断投入是否有回报）；容量规划按成本分布设计
