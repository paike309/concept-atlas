## 一句话定义

**中文**：让模型交替产出"推理"与"动作"、并用观察结果修正下一步的循环范式，以及在此基础上演化出的多种规划结构。

**English**: A loop where the model alternates between reasoning and acting, revising its next step based on observations — plus the planning structures derived from it.

## 我的理解

ReAct 的关键贡献不是"让模型思考"，而是**把推理写进上下文，使它成为后续决策的条件**。这与思维链的作用机制一致：显式化的中间步骤变成后续 token 可依赖的上下文。

它同时解决一个更实际的问题：**没有中间文本，工具调用就是盲目的。** 有了"我打算做什么、为什么"的记录，出错时可以定位到是哪一步的判断错了——这直接衔接[轨迹可观测性](trajectory-observability.md)。

**规划范式的谱系可以按"决策发生在什么时候"来分：**

| 范式 | 决策时机 | 优势 | 风险 |
|---|---|---|---|
| 边做边想（ReAct） | 每一步 | 适应性强 | 短视、容易绕圈 |
| 先规划再执行 | 开始前一次性 | 全局性强 | 计划基于错误前提 → 系统性偏离 |
| 分层 | 外层计划 + 内层执行 | 计划可被修正 | 结构复杂，两层都要调 |

三者的取舍是同一个权衡：**灵活性 vs 一致性**。任务路径越不确定，越靠前；路径越明确，越靠后——甚至可以退化成 Workflow。

## 核心机制

**循环单元**：Thought（当前判断）→ Action（工具调用）→ Observation（结果）→ 下一轮 Thought。

**终止**：模型给出最终答案，或外部约束触发（见[终止条件与预算](termination-and-budget.md)）。

**计划表示**：自然语言清单、结构化步骤列表、或待办状态机。**结构化程度越高，越容易被程序检查与修正。**

**计划修正**：Plan-and-Execute 的成败关键在"**什么时候允许改计划**"。只执行不修正会越走越偏。

**反思（reflection）**：让模型在失败后回看轨迹并调整策略，属于对循环的元层干预。它需要触发条件，不能每轮都做。

## 边界：它不是什么

- **与 [Workflow](agent-loop.md) 的区别**：路径是否预先确定。**能列出确定步骤时就不该用规划范式。**
- **与思维链的区别**：CoT 是单次前向内的推理展开，**不产生外部动作**；ReAct 的推理与工具执行交替发生，观察结果会反过来改变后续推理。
- **与多智能体的区别**：多智能体是并行结构；规划范式是单条控制流的结构。两者正交。

## 常见误解

1. **ReAct 就是让模型输出一个 Thought 字段** → 格式是表象。实质是"**用观察结果修正下一步**"——如果观察结果不改变后续决策，那就不是 ReAct。
2. **先做详细计划总是更好** → 计划基于当前信息。**信息不足时，详细计划会锁死错误方向**，且比没有计划更难纠正。
3. **规划能让 Agent 更可靠** → 规划改变的是**误差累积的方式**，不消除误差。
4. **反思总能改善结果** → 反思会引入新的错误，也消耗预算。要有触发条件与次数上限。

## 应用场景

- **该用**：路径不确定、需要根据中间结果调整、工具组合空间大
- **不该用**：路径固定（用 Workflow）、单步任务、结果必须完全可复现
- **判断依据**：先写一遍"理想情况下这个问题该怎么解"。**如果能列出确定的步骤序列，就不要用 Agent**；列不出来，再看步骤间的依赖是否需要动态调整
