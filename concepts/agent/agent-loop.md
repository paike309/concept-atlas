## 一句话定义

**中文**：由模型自身决定下一步动作、执行后再回到模型的闭环——观察、决策、行动、再观察，直到任务完成或预算耗尽。

**English**: A closed loop in which the model itself chooses each next action, observes the result, and re-decides — repeating until the task terminates or a budget is exhausted.

## 我的理解

判断一个系统是不是 Agent，只需要问一个问题：**下一步做什么，是谁决定的？**

- 由人预先写死在代码或流程图里 → 那是 **Workflow**，模型只被当作一个函数调用。
- 由模型在运行时根据当前状态产生 → 那是 **Agent**。

这个区分决定了系统的可预测性和调试方式。Workflow 的正确性可以静态推理（看代码就知道会走哪条路），Agent 的正确性只能靠运行轨迹来观察，同样的输入两次可能走不同路径。

另一件常被忽略的事：**Agent 的状态载体就是上下文**（见 [上下文窗口](../ai/context-window.md)）。它没有内部状态变量，每一步的"我做到哪了"完全依赖把历史重放进上下文。所以上下文一旦被截断或污染，Agent 会"失忆"或"记错"，表现为重复动作或目标漂移。

## 核心机制

一轮循环的四步：

1. **观察**：把用户输入、工具返回值、报错信息追加进上下文
2. **决策**：模型输出下一步——可能是调用某个工具（含参数），也可能是给出最终答案
3. **行动**：外部运行时执行工具，把结果回灌
4. **判定**：检查终止条件（拿到最终答案 / 达到步数上限 / 超时 / 预算耗尽 / 人工中断）

**让它能"做事"的部分不在模型里**，而在外部运行时：

- **工具定义**：名字、用途描述、参数模式（通常是 JSON Schema）。描述写得好不好，直接决定模型用不用得对。
- **协议**：目前主流是 MCP（Model Context Protocol），把"工具方实现一次、所有模型应用都能调用"标准化。可以类比成 USB-C：否则每个"应用 × 工具"组合都要单独对接。
- **循环控制**：步数上限、单步超时、成本上限。**必须外部强制**，模型自己不会停。

**终止是设计出来的，不是涌现出来的。** 一个没有步数上限、没有超时、没有预算的循环，等于把失控风险交给模型。

## 边界：它不是什么

- **与 Workflow 的区别**：见「我的理解」。补充一点：两者不是优劣关系。**能用 Workflow 解决的不要用 Agent**——路径确定时，Workflow 更便宜、更快、可测试。Agent 的价值只在"路径事先无法枚举"的场景。
- **与"带工具调用的单次对话"的区别**：单次工具调用 + 回答只是一次前向 + 一次执行，没有回到模型的第二次决策。有循环才叫 Agent。
- **与 [上下文窗口](../ai/context-window.md) 的区别**：窗口是约束条件（能读多少），循环是控制流（怎么推进）。循环跑不动通常不是模型不行，而是上下文预算没管好。
- **与"多智能体"的区别**：多智能体是把一个循环拆成多个循环 + 协作协议。它增加的是并行度和职责隔离，不是能力上限；同时引入通信成本与一致性问题——多数场景下单 Agent + 好工具就够了。

## 常见误解

1. **能调工具就是 Agent** → 单次工具调用不是循环。区分点是有没有"根据结果再决策"。
2. **循环越多轮效果越好** → 步数增加的同时，上下文被工具输出填满、错误累积、目标漂移概率上升。实测常常在若干轮后质量下降而非上升。
3. **给个好模型就够了** → 工具描述含糊、返回结果结构混乱、缺终止条件，再强的模型也会绕圈。工程质量的权重不低于模型选择。
4. **Agent 会自己学会用工具** → 它只是在给定描述下选择调用。描述没写清楚的能力，它基本不会用，也不会自己发现。

## 应用场景

- **该用 Agent**：步骤数量事先未知、需要根据中间结果改路线、工具组合空间大。典型是排查类、研究工作类任务。
- **不该用 Agent**：路径固定的批处理（用 Workflow）、一次性问答（单次调用就够）、结果必须可复现的场景（Agent 的非确定性是致命伤）。
- **必须配套的四样东西**：步数上限、单步超时、成本上限、可回放的轨迹日志。缺任何一样，上线就是把不确定性直接暴露给用户。

## 自测

1. 一个系统会根据用户问题在三个预定义流程里选一个走。它是 Agent 还是 Workflow？判断依据是哪一条？
2. Agent 连续三轮调用同一个工具、参数几乎相同，最可能的原因在上下文、工具描述、还是模型能力？
3. 为什么要由外部强制终止条件，而不是在提示词里写"完成任务后请停止"？
