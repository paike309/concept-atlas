## 一句话定义

**中文**：跨越单次会话保留并检索信息的机制，使 Agent 不必依赖上下文重放。

**English**: Mechanisms that retain and retrieve information across sessions so an agent does not rely on replaying context.

## 我的理解

先破除一个误解：**这不是模型的记忆。**

模型无状态（见[上下文窗口](../ai/context-window.md)）。所谓长期记忆完全是**外部系统**：把信息写出去，需要时检索回来，再放进上下文。

所以它本质上是 [RAG](../ai/rag.md) 的一个特例——区别只在语料是**自己产生的**。这带来两个 RAG 没有的问题：

**1. 写入质量不可控。** RAG 的语料是人工整理的文档；记忆的语料是 Agent 自己写的，可能包含错误、重复、过时甚至被注入的内容。**未经验证的记忆会变成持续污染源**——它会在之后的每一次检索里反复出现。

**2. 检索时机难判断。** 文档检索是任务驱动的（我知道该查什么）；记忆检索需要模型自己意识到"我可能记得相关的东西"，这一步经常失败。

还有一个取舍：记得越多，检索越难区分相关与不相关。所以**遗忘机制不是可选项**。

## 核心机制

**三种存储形态**：结构化（键值、数据库记录）、向量化（嵌入检索）、图结构化（实体与关系）。

**写入策略**：

| 策略 | 特点 |
|---|---|
| 显式写入（模型判断"值得记"） | 最省，但会漏 |
| 自动摘要（每轮/每阶段） | 全面，但有损且可能写入错误 |
| 外部写入（系统记录事实） | 可控，但需要预定义"什么算事实" |

**检索时机**：任务开始时注入（简单，但会塞入无关内容）或按需触发（省上下文，但依赖模型主动判断）。

**冲突处理**：新旧记忆矛盾时怎么办——覆盖、保留两版、还是标记待确认。**没有策略就会得到互相矛盾的上下文。**

**遗忘**：按时间衰减、按访问频率淘汰、或显式删除。涉及个人数据时，**删除能力是合规要求，不是优化**。

**隔离**：多用户/多租户必须严格隔离，否则记忆会串号——这是这类系统最严重的故障类型。

## 边界：它不是什么

- **与 [RAG](../ai/rag.md) 的区别**：语料来源（自己 vs 外部），以及**写入路径是否可控**。这是两者最实质的差别。
- **与上下文压缩的区别**：压缩是**当前任务内**的腾挪；记忆是**跨任务**保留。
- **与微调的区别**：微调把信息编进权重，**不可检索、不可删除、不可审计**，因此不适合承担"记忆"的角色。

## 常见误解

1. **这是模型的记忆** → 是外部系统，模型每次都只是"读到"。
2. **记得越多越好** → 检索区分度下降，噪声增加。
3. **可以无限累积** → 需要遗忘与清理策略，否则会持续退化。
4. **记忆是可信的** → Agent 自己写的内容可能有错，也可能被注入污染。

## 应用场景

- **该用**：需要跨会话连续性、用户偏好、长期项目上下文
- **不该用**：一次性任务；强隐私要求且无法保证隔离的场景
- **判断依据**：先问"这些信息**必须**跨会话保留吗"。不是必须，就不要引入——复杂度与污染风险都很高，收益却很有限
