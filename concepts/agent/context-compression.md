## 一句话定义

**中文**：在不破坏任务连续性的前提下减少上下文占用的具体手段——确定性裁剪、摘要、替换为引用。

**English**: Concrete techniques for reducing context usage without breaking task continuity — deterministic trimming, summarization, and replacement with references.

## 我的理解

[上下文预算管理](context-budget.md)讲的是"该回收哪一类"，这里细化到"**具体怎么压**"。

判断标准只有一条：**压缩之后，模型能否做出同样的决策。**

三类手段的性质完全不同：

| 手段 | 有损性 | 适用 |
|---|---|---|
| 确定性裁剪（去重、截断长字段、结构化提取） | 无损或近无损 | **优先做** |
| 摘要 | 有损，且由模型生成会引入新错误 | 过程性内容（已完成的子任务中间步骤） |
| 替换为引用（路径、ID） | 无损 | 以后还会用到、且能重新取到的内容 |

一条经验判断：**先问"这段内容以后还会不会用到"，再问"用的时候能不能重新拿到"。** 两个都是"是"→ 换成引用；能重新拿到 = 不丢信息，这是最干净的压缩。

## 核心机制

**摘要的层次**：单轮摘要 → 阶段摘要 → 全局摘要。层次越多，失真累积越重，所以要**限制层级数**。

**不可摘要的内容**（必须原样保留，最好放在固定区块）：

- 任务原始目标
- 硬约束：格式要求、禁止事项、安全边界
- 用户明确指定的偏好

**结构化提取**：工具返回的长 JSON 只留模型真正需要的字段。**这一步常常省下绝大部分占用，而且对被保留字段而言完全无损**——收益/风险比最高。

**触发时机**：按占用比例阈值触发（如 70%），不要等撞上限才压。撞上限时已经没有腾挪余地，只能做最激进的裁剪。

**必须验证**：压缩后跑回归集，确认任务成功率未下降。**压缩是有可能压掉关键线索的**，而且症状是"模型突然变笨"，很容易被误诊。

## 边界：它不是什么

- **与[上下文预算管理](context-budget.md)的区别**：后者是分配与回收的**策略**，这里是执行的**手段**。策略决定"压哪类"，手段决定"怎么压"。
- **与 [RAG](../ai/rag.md) 的区别**：RAG 决定把什么拿进来，压缩决定把什么拿出去。一进一出。
- **与向量化存储的区别**：向量化用于**跨会话**的长期检索；压缩服务于**当前任务**的即时腾挪。用错了会把当前任务的关键信息推到一个检索不回来的地方。

## 常见误解

1. **摘要等于无损压缩** → 有损，且摘要本身可能出错。多次摘要会累积失真。
2. **压缩比例越高越好** → 压掉关键线索后，症状是模型"突然变笨"，且难以归因。
3. **所有内容都可以摘要** → 原始目标与硬约束不能。**这是[目标漂移](failure-modes.md)最常见的起点。**
4. **压缩是纯工程问题，不需要验证** → 必须跑回归集，否则会静默降低质量。

## 应用场景

- **该做**：长任务、工具返回体量大、多轮对话超过十轮
- **判断依据**：**压缩后能否通过之前的失败用例集**——这是唯一可靠的检验方式
- **优先顺序**：先做结构化提取（收益最大、风险最低），再做引用替换，最后才摘要
