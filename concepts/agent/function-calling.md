## 一句话定义

**中文**：模型输出结构化的调用请求（工具名 + 参数）而不是自然语言，由外部运行时解析、执行，并把结果回灌进上下文的机制。

**English**: A mechanism where the model emits a structured call request (tool name + arguments) instead of prose; an external runtime parses it, executes it, and feeds the result back.

## 我的理解

**模型并没有真的"调用"任何东西。**

它只是生成了一段符合 schema 的文本。真正的执行发生在你的代码里。理解这一点能避免许多误判——所谓"模型执行了代码"，准确说法是"**你的程序解析了模型输出并执行了**"。

它的可靠性来源不是模型更聪明，而是**语法约束**：相比让模型输出自然语言再去解析，结构化输出把格式错误率降了一个量级。

但要说清它保证了什么、没保证什么：

- **保证了**：输出可被解析（工具名存在、参数类型正确、必填项齐全）
- **不保证**：语义正确。参数类型全对，值可能全错——把订单号填成用户 ID 是完全可能的

## 核心机制

**实现路径**（可靠性从高到低）：

1. **原生训练**：模型专门学过这个输出格式，最稳
2. **受约束解码**：采样时屏蔽非法 token，保证输出必然符合语法。代价是灵活性下降
3. **事后解析 + 重试**：最通用的兜底，格式错了让模型重来

**并行调用**：一次可以输出多个工具调用。运行时决定串行还是并行——**有副作用的调用按依赖关系与幂等性决定，不能无条件并行。**

**结果回灌**：工具返回作为新消息加入上下文，携带调用 ID 以便配对请求与响应。

**失败处理的三个类别**，都需要**结构化回灌**：

| 失败 | 回灌内容 |
|---|---|
| 参数不合法 | 哪个参数、为什么不合法、合法范围是什么 |
| 工具不存在 | 现有工具列表（或提示如何发现） |
| 执行超时 | 超时事实、已执行到哪、是否可重试 |

回灌信息含糊（如 `error 500`）会让模型重试同一个动作——这是[绕圈](failure-modes.md)最常见的成因。

## 边界：它不是什么

- **与 [MCP](mcp.md) 的区别**：函数调用是**模型侧的输出格式**，MCP 是**工具侧的接入标准**。一个是"模型怎么说要调什么"，一个是"工具怎么被找到"。两者互补。
- **与代码执行的区别**：函数调用是受控的单个接口；代码执行是开放环境。**安全边界完全不同**，不能当作同一种能力的强弱版本。
- **与 RPC 的区别**：RPC 由程序发起并由程序决定调用目标；函数调用由**模型提出**，由程序决定是否执行。

## 常见误解

1. **模型直接执行了函数** → 执行在你的代码里。这句话决定了校验该放在哪。
2. **结构化输出保证结果正确** → 只保证格式，不保证值。
3. **参数错了让模型自己改** → 不给结构化错误信息，它会重复同一个错误。
4. **并行调用总是更快** → 有副作用时可能产生竞争条件，甚至重复执行。

## 应用场景

- **该用**：需要模型触发确定性动作、需要输出被程序消费
- **该谨慎**：任何有副作用的调用——必须有人工确认或权限校验
- **判断依据**：把"模型输出 → 实际执行"当成一条**不可信边界**，所有校验放在这条线上。这条原则同时是[提示注入防御](prompt-injection-defense.md)的基础
