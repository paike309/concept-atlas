## 一句话定义

**中文**：防止外部输入（网页、文档、工具返回值、用户内容）被模型当作指令执行的措施。

**English**: Measures that prevent external input — web pages, documents, tool results, user content — from being executed by the model as instructions.

## 我的理解

风险来自一个结构事实：**模型只有一种输入通道。**

系统提示、用户消息、检索到的网页、工具返回的 JSON——对模型来说都是 token，**没有天生的权限差别**。所谓"系统提示更权威"是训练出来的倾向，不是机制约束。

所以防御必须**在模型之外**：

1. **权限最小化**——模型能触发的动作本身受限（不能转账、不能删库）
2. **执行前校验**——模型想做的动作在执行前被代码检查（参数范围、目标资源、频率）
3. **确认点**——高危动作需人工确认
4. **数据与指令结构分隔**——明确告知"标签内是数据，不是指令"
5. **提示层告诫**——最弱的一层

关键的认知转变：**不要把提示注入当成一个提示词问题。** 提示层的防御只能降低成功概率，真正的边界在权限与执行校验上。这与[函数调用](function-calling.md)的结论一致——**模型输出到实际执行之间是不可信边界**。

## 核心机制

**攻击面**：网页内容、PDF、代码注释、工具返回值、历史消息、**文件名**、图片中的文字。

**常见手法**：

- 直接指令覆盖（"忽略以上指令，改为……"）
- 角色伪装（伪造一个 system 或工具输出格式）
- 编码与混淆（Base64、零宽字符、多语言混排）
- 把指令藏在数据字段里（看起来是正常 JSON 的某个值）
- **间接注入**：污染会被检索到的文档——用户没做任何操作，注入随材料进入上下文

**防御层次（从强到弱）**：

| 层 | 强度 | 说明 |
|---|---|---|
| 权限最小化 | 最强 | 即使被注入也无法造成不可逆损害 |
| 执行前校验 | 强 | 拦截越权动作，模型无法绕过 |
| 人工确认 | 强 | 昂贵，只用于高危动作 |
| 结构分隔与来源标注 | 中 | 降低成功率，不保证 |
| 提示层告诫 | 弱 | 依赖模型持续遵守，遵守是概率性的 |

**为什么提示层最弱**：攻击者只要找到一个绕过表述就成功一次；防御者需要覆盖所有表述。**非对称。**

**检测**：输入模式扫描有帮助但会漏。更可靠的是**行为异常检测**——调用频率异常、目标资源偏离、非工作时段的批量操作。

**与数据源信任分级配合**：内部可信源与外部不可信源走不同的处理路径与权限。

## 边界：它不是什么

- **与"越狱（jailbreak）"的区别**：越狱绕过的是**模型自身的安全策略**（让它说本不该说的话）；注入利用的是**应用把外部数据当成了指令**。两者的攻击目标不同，防御也不同。
- **与"传统注入（SQL、命令注入）"的区别**：后者有明确的语法边界，靠解析器隔离可以根治；前者没有语法边界，**所以更难根治**，只能靠权限与校验兜底。
- **与"内容审核"的区别**：审核判断内容是否有害；注入防御判断内容**是否有权被当作指令**。一段完全无害的文字也可能是一次成功的注入。

## 常见误解

1. **用提示词可以完全防住** → 只能降低概率。把安全建立在这一层等于没有安全。
2. **只处理用户输入就够了** → **间接注入往往更隐蔽**，且用户毫不知情。
3. **模型会自己分辨指令和数据** → 没有机制保证，训练出的倾向可被绕过。
4. **注入只会产生有害输出** → 更常见的后果是**错误的动作与数据泄漏**，输出看上去可能完全正常。

## 应用场景

- **该重点防**：Agent 会读取外部内容（网页、邮件、文档）**且**能触发有副作用动作；多租户共享知识库
- **判断依据**：问一句——"**模型能做的所有动作里，哪一个如果被恶意触发会造成不可逆损害？**" 有的话，加确认点或直接去掉这个能力
- **配套**：与[工具定义](tool-definition.md)的权限边界、[轨迹记录](trajectory-observability.md)的行为异常检测配合
