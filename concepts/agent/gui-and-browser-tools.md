## 一句话定义

**中文**：让 Agent 通过操作界面（点击、输入、导航）完成任务，而不是通过调用结构化接口。

**English**: Letting an agent accomplish tasks by operating a user interface — clicking, typing, navigating — instead of calling a structured API.

## 我的理解

**GUI 操作是"没有 API 时的兜底手段"，它的核心代价是脆弱性与安全性，而不是成本。**

与调用 API 相比，界面操作有三个结构性弱点：

1. **接口不稳定。** 页面结构一改，依赖 DOM 的选择器就失效——**而改动方完全不知道你依赖了它**。这是与 API 的本质差别：API 有版本与兼容性承诺（见[契约与接口设计](../software/contract-design.md)），界面没有。
2. **状态易失且带外。** 登录态、验证码、弹窗、会话过期、上传下载，都发生在模型看不到的地方。**Agent 的"上下文"里只有它自己发出的动作，没有环境的真实状态**，因此同一个动作在第二次运行时可能因为弹窗而失败。
3. **输入不可信程度最高。** 网页内容由第三方控制，**这是间接提示注入最典型的载体**——页面里任何一段文字都可能被模型当成指令（见[提示注入防御](prompt-injection-defense.md)）。

由此得到两条实践结论：

- **优先级永远是"有 API 就不用 GUI"**。结构化接口有契约、可测试、可版本化；界面操作应被视为**覆盖 API 缺失场景的最后手段**。
- **把动作的"意图"与"实现"分开**。让 Agent 表达"点击登录按钮"这类语义目标，由工具层负责定位元素（多重选择器、等待策略、重试）。**让模型直接生成 CSS 选择器，等于把最脆弱的细节交给最不可靠的推理。**

## 核心机制

**两类实现路径**：

| 路径 | 做法 | 特点 |
|---|---|---|
| DOM 层操作 | 通过选择器定位元素并触发事件 | 快、可断言；**依赖页面结构** |
| 视觉层操作 | 截图 + 坐标点击（"看屏幕"） | 不依赖 DOM；**慢、昂贵、精度受分辨率限制** |

多数实现是混合的：优先用 DOM 定位，必要时回退到视觉。

**稳定性的四个来源**（按收益排序）：

| 手段 | 作用 |
|---|---|
| 语义化定位（按可访问性角色/文本，而非 DOM 路径） | 页面改版时存活率最高 |
| 显式等待条件（等元素可见/可点击，而非固定 sleep） | 消除大部分"偶发失败" |
| 动作的幂等与重试（配合状态检查） | 网络抖动与渲染延迟可自愈 |
| 断点续跑（记录已完成的步骤） | 长流程失败后不必从头再来 |

**会话与状态管理**：登录态、cookie、本地存储、多标签页，都是"模型看不见但决定成败"的状态。工程上的常见做法是把会话存成可复用的配置文件，**并把"是否已登录"做成一个可查询的前置条件**，而不是靠模型自己"记得"。

**安全边界**（这一块比操作本身更重要）：

- **浏览器必须在隔离环境中运行**（容器/沙箱），且**默认不携带真实用户的长期凭据**
- 站点访问范围应当**白名单化**（允许列表），否则被注入的 Agent 可以导航到任意外部地址
- 下载与上传要走受控目录，**不能直接落盘到工作目录**
- 所有从页面读到的文本，进入上下文时都应当被标记为**不可信内容**

**验证与回放**：界面操作的成功判据必须**基于页面的可观察状态**（某个元素出现、某个文本变化），而不是"动作没有报错"。**"点过了"不等于"点成功了"**——这是这类工具最常见的假成功。每一步的状态快照应当进入[轨迹](trajectory-observability.md)，否则失败后无法判断是哪一步偏离了。

## 边界：它不是什么

- **与[工具定义](tool-definition.md)的区别**：那张卡讲怎么把一个能力描述给模型；这张讲某**一类特别脆弱的能力**（操作界面）该怎么设计。描述质量在这里尤其关键，因为动作空间大且后果不可逆。
- **与[代码执行沙箱](code-execution-sandbox.md)的区别**：沙箱执行的是**模型生成的代码**，风险在于代码本身；GUI 工具执行的是**对界面的操作**，风险在于它触碰的是真实业务系统（下单、转账、发消息）。**后者的副作用通常更直接。**
- **与 API 调用的区别**：见「我的理解」。判断依据很简单——**这个系统有没有稳定的接口？有就用接口。**
- **与"爬虫"的区别**：爬虫是**只读**地抓取内容；GUI 工具会**改变远端状态**。这决定了它们在权限与审计上的要求完全不同。

## 常见误解

1. **有界面就能自动操作** → 稳定性依赖页面结构、时序与会话状态，三者都不受你控制。
2. **让模型自己写选择器更快** → 把最脆弱的细节交给最不可靠的推理，维护成本转嫁给未来。
3. **动作没报错就是成功** → 必须用页面状态验证，否则会产生"假成功"。
4. **用固定 sleep 等页面加载更简单** → 它既慢又不可靠，应改为等待明确条件。
5. **浏览器里用的是用户真实账号** → 一旦被注入操纵，影响的是真实资产。
6. **页面内容只是数据，不会被当作指令** → 这正是间接提示注入的入口。

## 应用场景

- **该用**：目标系统没有可用 API（内部旧系统、仅界面可用的第三方服务）
- **不该用**：有稳定 API 的场景；高频调用场景（延迟与脆弱性成本过高）
- **判断依据**：问四句——**有 API 吗**？**失败后能否用页面状态判断**？**运行环境与凭据是否隔离**？**站点访问范围是否白名单化**？
- **配套**：隔离环境 + 白名单 + 受控下载目录；每步状态快照进[轨迹](trajectory-observability.md)；高风险动作（提交、支付、发布）插入[人在回路确认](human-in-the-loop.md)
