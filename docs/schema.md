# 卡片规格 · Schema

这个库唯一的硬约束。加卡之前读一遍，之后按模板填就行。

---

## 1. 位置与命名

```
concepts/<领域>/<english-slug>.md
```

- **领域**只有三个：`ai` / `agent` / `software`
- **slug**：全小写英文，单词间用连字符。`attention-mechanism.md`、`context-window.md`
- **不要用中文文件名**。路径会进 URL、进命令行、进各种工具，中英混排会在编码上反复出问题。中文只出现在标题和正文里
- 同一目录下不重名

需要二级分组时，用属性表的「领域」行写（如 `AI / 模型架构`），**不要**再建一层目录——目录层级一深，卡片就找不到了。

---

## 2. 属性表

每张卡第一行是 H1 标题，紧接着是属性表：

```markdown
# 注意力机制 · Attention Mechanism

| 属性 | 值 |
|---|---|
| 英文 | Attention Mechanism |
| 别名 | Attention · 自注意力 Self-Attention |
| 领域 | AI / 模型架构 |
| 层级 | 基础 |
| 前置 | 无 |
| 相关 | [Transformer 架构](transformer.md) |
| 状态 | `stable` |
| 信源等级 | `link-checked` 链接已核验，正文未核 |
| 最近核对 | 2026-09-14 |
```

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| 英文 | 是 | 英文术语 | 用领域内通用写法，不用自创译名 |
| 别名 | 否 | 顿号或 `·` 分隔 | 其他叫法、缩写、常见错写。方便检索 |
| 领域 | 是 | `<领域> / <主题>` | 一级只能是 ai / agent / software |
| 层级 | 是 | `基础` / `进阶` / `前沿` | 决定从哪读起。**不要全都标"基础"** |
| 前置 | 是 | 概念链接，没有就写"无" | 读它之前需要先懂什么。**这栏不能空着** |
| 相关 | 否 | 概念链接 | 平级、易混、需对照看的概念 |
| 状态 | 是 | `stub` / `stable` / `stale` | 见下 |
| 信源等级 | 是 | `unverified` / `link-checked` / `machine-confirmed` / `human-reviewed` | 见下 |
| 最近核对 | 是 | `YYYY-MM-DD` | 最近一次实质修改 |

然后是**参考来源**（有序列表，链接写 `<url>` 形式），再接一条 `---` 分隔线，之后才是正文。

---

## 3. 状态

| 取值 | 含义 |
|---|---|
| `stub` | 只有框架，正文未写或大半为占位 |
| `stable` | 八节齐全，内容自洽，可以依赖 |
| `stale` | 可能已过期，待复核 |

「最近核对」超过一年未更新，按 `stale` 处理。

---

## 4. 信源等级

| 取值 | 前提条件 |
|---|---|
| `unverified` | 内容未经任何核查 |
| `link-checked` | **来源链接已机器核验**：链接可达，且目标资源与卡片声称的一致（arXiv 编号与论文标题逐条比对、页面标题核对）。**但不保证该资源支撑正文的具体表述**，正文也未改写 |
| `machine-confirmed` | 已**逐条**确认每个来源确实支撑它在「来源对应」里标注的那一段 |
| `human-reviewed` | 正文逐句读过，且「我的理解」是自己的话 |

**四个等级是递进的，不要跳级。** `link-checked` 只解决"链接是否指对了东西"；`machine-confirmed` 才开始回答"内容是否有据"；`human-reviewed` 回答的是"这是不是我真的懂了"。

**标 `human-reviewed` 的唯一前提是「我的理解」确实由自己写。** 照抄来源再标 `human-reviewed`，会让这一栏彻底失去意义——而它是这个库里唯一能区分"真懂"和"存过"的标记。

**另一个必须守住的纪律**：卡片被改动之后，等级要退回 `link-checked`。因为改动过就意味着上一次核查不再覆盖当前内容。这是最容易自我欺骗的一步。

---

## 5. 正文八节

顺序固定，节标题逐字一致：

```
## 一句话定义
## 我的理解
## 核心机制
## 边界：它不是什么
## 常见误解
## 应用场景
## 自测
## 来源对应
```

| 节 | 写法要求 |
|---|---|
| 一句话定义 | **中文**：一句话说清是什么。不出现"等等""相关技术"这类含糊词。**English**：一句，贴近领域的标准定义 |
| 我的理解 | 可以打比方、可以用类比、允许不严谨。**这一节不能由 AI 代劳。** 写不出来说明还没懂，把状态标成 `stub` 放着 |
| 核心机制 | 按因果顺序写，不按教科书目录写。涉及量级的地方给数字（复杂度、参数量、延迟、显存），不给"很大""很快" |
| 边界：它不是什么 | 列出最易混的两三个邻近概念，逐个说清差在哪。这里用**相对链接**指向别的卡 |
| 常见误解 | 每条写成「误解 → 实际情况」。只写真踩过的，不凑数 |
| 应用场景 | 写"什么条件下该用 / 不该用"，给判断依据。不写广告式清单 |
| 自测 | 三题左右，一分钟内能答完。**问"为什么""怎么判断"，不问名词解释** |
| 来源对应 | 逐条说明每个来源支撑了上面哪一段。**找不到来源支撑的段落要单独标出并注明是自己的推断** |

## 6. 链接写法

用标准 markdown 相对链接，GitHub 上可直接点：

- 同目录：`[Transformer 架构](transformer.md)`
- 跨领域：`[Agent 循环](../agent/agent-loop.md)`
- 指向还没写的概念：不要留死链，写成 `分词（Tokenization，[待写](../roadmap.md)）`

Mermaid 图里的节点**不加链接**（GitHub 对图内链接支持不稳定），链接放在图下方的表格里。

---

## 7. 卡内关系只有两种

| 关系 | 属性表字段 | 含义 |
|---|---|---|
| 前置 | `前置` | 读这张卡之前需要先懂的。这是**学习顺序**，不是分类 |
| 相关 | `相关` | 平级对照。用来提示"这两个容易混" |

不要把"前置"当标签用。判断标准很简单：**如果一个不懂前置的人读这张卡会读不下去，它就是前置；只是提了一句，那是正文里的链接。**

## 8. 加卡检查清单

> main 受分支保护，改动必须走 PR 且通过 `validate` 检查（见 [README 的「变更怎么进 main」](../README.md#变更怎么进-main)）。脚本能查的是下面第 1、2、4 项这类结构问题；**它查不了内容对不对**。

- [ ] 文件名是全小写英文短名
- [ ] 属性表九行齐全，「前置」栏填了（可以为"无"）
- [ ] 参考来源的每条链接都亲自打开过
- [ ] 信源等级与实际核对程度一致（**不要跳级**：链接可达只是 `link-checked`）
- [ ] 如果这次改动了正文，把等级退回 `link-checked`，并在 [`verification-log.md`](verification-log.md) 记一笔
- [ ] 「我的理解」是自己的话
- [ ] 「边界」一节链接到了邻近概念
- [ ] 「来源对应」说明了每个来源支撑哪一段；属于自己的推断已明确标出
- [ ] 回 `roadmap.md` 把对应条目勾上
- [ ] 若别的卡曾以「待写」提到它，把那些位置改成链接
